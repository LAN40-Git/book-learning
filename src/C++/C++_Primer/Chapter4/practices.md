### 4.3

```
我认为这种设计是可以接受的。
一方面，不规定二元运算符的求值顺序，编译器可以自由重排操作数的计算顺序，充分进行指令优化，生成效率更高的目标代码。
另一方面，该做法确实带来潜在缺陷：若运算符左右操作数带有副作用并且修改同一变量，由于求值顺序不确定，表达式会产生未定义行为，程序结果不可移植。但是该风险可以通过程序员的编码规范来避免：不在同一个表达式内多次修改同一个对象，把复杂带副作用的表达式拆分为多条语句。
综合来看，以程序员写代码时稍加注意为代价，换取普遍情况下更好的运行性能，这个权衡是合理的。
```

### 4.7

**溢出含义**：当算术运算得到的结果超出该数据类型可以保存的取值范围时，就发生溢出。有符号整数溢出是 C++ 中的未定义行为，程序运行结果不确定。

1. `short(32767) + 1`
2. `2147483647 * 2`
3. `-2147483648 - 1`

### 4.8

1. `&&`：**先左，短路**；左为假，右边不求值。
2. `||`：**先左，短路**；左为真，右边不求值。
3. `==` / `!=`：**没有规定求值顺序**，编译器可任选先算左或者先算右，不存在短路。

### 4.15

1. 赋值右结合，原式拆解：`dval = ( ival = (pi = 0) )`
2. `pi = 0`合法：把 0 赋值给 int 指针 pi，指针置空。
3. `ival = pi`非法：`pi`是`int *`指针类型，`ival`是普通 int 整型，**指针不能直接赋值给 int 变量，类型不兼容**，编译报错。
4. 修改：三条独立赋值语句，分别给指针、int、double 赋值为 0。

### 4.16

| 语句                         | 实际行为                                                     | 问题根源                                       | 修改后的正确写法           |
| ---------------------------- | ------------------------------------------------------------ | ---------------------------------------------- | -------------------------- |
| (a) `if (p = getPtr() != 0)` | 由于`!=`优先级高于`=`，等价于`p = (getPtr() != 0)`。先判断函数返回值是否非 0，把比较结果`1`或`0`赋值给指针`p`，而非将函数返回的指针赋值给 p 再判断。 | 运算符优先级导致运算顺序和预期不符，缺少括号。 | `if ((p = getPtr()) != 0)` |
| (b) `if (i = 1024)`          | 执行赋值`i = 1024`，表达式结果为 1024（非 0），if 条件永远为真，不是判断 i 是否等于 1024。 | 误用赋值运算符`=`代替相等比较运算符`==`。      | `if (i == 1024)`           |

### 4.18

> 使用前置`*++pbeg`：① 不会输出 vector 的第一个元素；② 若 vector 中没有负数，循环最后会对`end()`解引用，产生**未定义行为（程序出错）**。

> 核心区别：
>
> - 后置`pbeg++`：表达式返回**原来的值**，之后迭代器自增；
> - 前置`++pbeg`：迭代器先自增，表达式返回**自增之后的值**。

### 4.19

| 表达式                         | 是否合法                | 含义 / 问题说明                                              | 修改方案                                                     |
| ------------------------------ | ----------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| (a) `ptr != 0 && *ptr++`       | 合法                    | `&&`短路求值：先判断`ptr`不是空指针；若指针非空，解引用取当前指向元素参与逻辑判断，**之后指针 ptr 向后自增**。若 ptr 为空，不会执行`*ptr++`，避免空指针解引用。⚠️注意：自增的是指针，不是指针指向的数值。 | 如果意图是自增指针指向的值：`ptr != 0 && (*ptr)++`           |
| (b) `ival++ && ival`           | 合法                    | `ival++`返回`ival`的旧值，然后`ival`完成自增。若旧`ival`为 0：短路，右侧`ival`不计算，`ival`依然 + 1；若旧`ival`非 0：拿自增后的新`ival`做右侧运算。 | 语法无错误，注意前后使用的是不同的`ival`值                   |
| (c) `vec[ival++] <= vec[ival]` | 不合法（未定义行为 UB） | `<=`没有规定左右操作数求值顺序。表达式内既修改`ival`又读取`ival`，编译器不确定先算左边还是右边，结果完全不可预测。 | `vec[ival] <= vec[ival + 1];`需要自增则比较完成后执行`ival++` |

### 4.20

| 表达式                 | 是否合法 | 含义 / 错误说明                                              | 修改方案                                            |
| ---------------------- | -------- | ------------------------------------------------------------ | --------------------------------------------------- |
| (a) `*iter++`          | 合法     | 等价`*(iter++)`。后置 ++：先对迭代器原值解引用，获取 string 对象，再将迭代器向后移动。 | 无需修改                                            |
| (b) `(*iter)++`        | 不合法   | `*iter`得到`string`对象，**string 类型不支持后置自增运算符**。 | 使用 string 成员函数修改字符串，如`(*iter)+="text"` |
| (c) `*iter.empty()`    | 不合法   | `.`优先级高于`*`，等价`*(iter.empty())`；迭代器`iter`没有`empty()`成员，`empty()`是 string 的成员。 | `(*iter).empty()` 或 `iter->empty()`                |
| (d) `iter->empty();`   | 合法     | 迭代器解引用，调用指向的`string`的`empty()`，判断字符串是否为空。 | 无需修改                                            |
| (e) `++*iter;`         | 不合法   | 等价`++(*iter)`；`*iter`得到`string`对象，**string 不支持前置自增运算符**。 | 使用 string 成员函数修改字符串内容                  |
| (f) `iter++->empty();` | 合法     | `->`优先级高于后置 ++；用迭代器当前值调用`empty()`，之后迭代器向后自增。 | 无需修改                                            |

1. `sizeof(数组名)`：数组名**不会退化为指针**，得到整个数组占用字节。
2. 数组赋值给指针变量后，**数组长度信息彻底丢失**；`sizeof(p)`只获取指针自身大小，和指向数组的元素数量无关。
3. 函数形参 `int arr[]` 等价 `int* arr`，已经退化，函数内部不能用`sizeof(arr)/sizeof(*arr)`求数组长度。

### 4.30

| 题号 | 原表达式           | 添加括号后（含义不变） | 优先级说明                                                   |
| ---- | ------------------ | ---------------------- | ------------------------------------------------------------ |
| (a)  | `sizeof x + y`     | `(sizeof x) + y`       | `sizeof`优先级高于`+`；先求`x`的大小，再与`y`相加。不能写成`sizeof(x+y)`，会改变语义。 |
| (b)  | `sizeof p->mem[i]` | `sizeof(p->mem[i])`    | 后缀`->`、`[]`优先级高于`sizeof`；先访问`p->mem[i]`，再求该元素大小。 |
| (c)  | `sizeof a < b`     | `sizeof(a) < b`        | `sizeof`优先级高于`<`；先求`a`的字节大小，再和`b`做小于比较。不能写成`sizeof(a < b)`。 |
| (d)  | `sizeof f()`       | `sizeof(f())`          | 函数调用`()`为后缀运算符，优先级高于`sizeof`；求取函数返回值类型大小，**不会执行函数 f**。 |
