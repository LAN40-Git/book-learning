### 4.3

```
我认为这种设计是可以接受的。
一方面，不规定二元运算符的求值顺序，编译器可以自由重排操作数的计算顺序，充分进行指令优化，生成效率更高的目标代码。
另一方面，该做法确实带来潜在缺陷：若运算符左右操作数带有副作用并且修改同一变量，由于求值顺序不确定，表达式会产生未定义行为，程序结果不可移植。但是该风险可以通过程序员的编码规范来避免：不在同一个表达式内多次修改同一个对象，把复杂带副作用的表达式拆分为多条语句。
综合来看，以程序员写代码时稍加注意为代价，换取普遍情况下更好的运行性能，这个权衡是合理的。
```

### 4.4

```
((12 / 3) * 4) + (5 * 15) + ((24 % 4) / 2)
过程：先计算12 / 3的结果，然后乘4得a，再计算5 * 15的结果得b，再计算24 % 4的结果，然后除以2得c，最终a+b+c就是最终结果。
结果：91
```

### 4.7

**溢出含义**：当算术运算得到的结果超出该数据类型可以保存的取值范围时，就发生溢出。有符号整数溢出是 C++ 中的未定义行为，程序运行结果不确定。

1. `short(32767) + 1`
2. `2147483647 * 2`
3. `-2147483648 - 1`

### 4.8

1. `&&`：**先左，短路**；左为假，右边不求值。
2. `||`：**先左，短路**；左为真，右边不求值。
3. `==` / `!=`：**没有规定求值顺序**，编译器可任选先算左或者先算右，不存在短路。
