### 3.12

| 序号 | 代码语句                           | 是否正确 | 执行结果 / 错误原因                                          |
| ---- | ---------------------------------- | -------- | ------------------------------------------------------------ |
| (a)  | `vector<vector<int>> ivec;`        | 正确     | 定义了一个空的 vector 容器，该容器的元素类型为`vector<int>`，当前容器大小为 0，未存放任何子 vector 对象。 |
| (b)  | `vector<string> svec = ivec;`      | 错误     | 拷贝初始化要求等号两侧容器的**元素类型必须完全匹配**。`ivec`的元素类型是`vector<int>`，`svec`的元素类型是`string`，二者类型不兼容，编译器无法完成拷贝操作，会触发编译报错。 |
| (c)  | `vector<string> svec(10, "null");` | 正确     | 创建了一个`string`类型的 vector 容器，容器内包含 10 个元素，且每个元素都被统一初始化为字符串`"null"`。 |

### 3.27

| 选项 | 代码                           | 是否合法 | 原因                                                         |
| ---- | ------------------------------ | -------- | ------------------------------------------------------------ |
| (a)  | `int ia[buf_size];`            | 非法     | `buf_size`是普通无符号变量，不是编译期常量表达式，C++ 标准规定数组长度必须为编译时常量，不能用普通变量定义数组大小 |
| (b)  | `int ia[4 * 7 - 14];`          | 合法     | `4 * 7 - 14`是字面量构成的常量表达式，编译阶段即可计算出固定数值，满足数组长度要求 |
| (c)  | `int ia[txt_size()];`          | 非法     | `txt_size()`是函数调用，返回值需要运行时才能确定，不属于编译期常量，不能作为数组维度 |
| (d)  | `char st[11] = "fundamental";` | 非法     | 字符串字面量`"fundamental"`包含 12 个可见字符，末尾还会自动追加`\0`结束符，总共需要 13 个 char 空间，数组仅分配 11 个元素，存储空间不足，初始化越界 |

### 3.29

1. 数组大小固定，运行时不能动态改变大小；vector 可以动态扩容。
2. 不做下标越界检查，容易产生未定义错误。
3. 数组不能直接拷贝和赋值，无法使用`=`完成整体复制。
4. 数组名大多场景退化为指针，丢失数组维度信息，函数传参无法获取数组长度。
5. 没有`push_back`、`size`等便捷接口，操作繁琐。
6. 动态数组需要手动管理内存，容易内存泄漏。

### 3.37

1. **程序意图**：利用指针逐个输出字符数组中的字符。
2. **代码缺陷**：字符数组`ca`没有字符串结束符`'\0'`。`while(*cp)`依赖`\0`判断结束，会造成数组越界访问。
3. **实际现象**：先打印`h e l l o`，之后读取内存乱码，行为未定义，可能乱码输出、程序崩溃。

### 3.38

指针的值是内存地址。两个指针相加，得到的是两个内存地址的和，这个结果不能代表任何数组元素的地址，没有实际业务含义。

指针运算的目的是定位数组中的元素：

1. 指针和整数相加：移动指针，访问数组其他元素；

2. 同数组两指针相减：得到两个指针之间相隔的元素个数；

   而两个指针的和，既不能得到有效元素地址，也得不到偏移量，没有任何实际意义，C++ 直接禁止该运算。
